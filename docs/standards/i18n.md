# Internationalization Standard

Travel is international by nature. Treat i18n as core, not polish.

Library: TBD per stack (must support ICU MessageFormat).
Locales: TBD with the first feature. Default locale: TBD.


## Strings

- No hardcoded user-facing text in code. Everything through keys.
- Keys: `<feature>.<screen>.<element>`, e.g. `trips.list.emptyTitle`.
- ICU messages for plurals and gender:
  `{count, plural, one {# stop} other {# stops}}`.
- Never build sentences by concatenation. Word order differs.
- Plan for +40% text length (German, Spanish). No fixed-width text.


## Dates and times

- Store instants in UTC (ISO 8601). Store the IANA time zone
  (`America/Bogota`) alongside when local time matters.
- A travel event happens in the **destination's** time zone. Display
  it there, and label the zone when it differs from the user's.
- Date-only values (a trip day) are not instants. Store as
  `YYYY-MM-DD` without time zone.
- Format with `Intl` / locale-aware APIs only. Never manual strings.
- Test daylight-saving transitions and date-line crossings.


## Money

- Store as integer minor units plus ISO 4217 currency code. Never
  floats.
- Format with locale-aware currency formatting.
- Conversions record the rate and its timestamp.


## Numbers, units, names

- Locale-aware number formatting (decimal and group separators).
- Distances: respect locale units (km or mi).
- Person names: one `displayName` field unless the feature needs more.
  Do not assume first/last order.
- Addresses: do not force one country's format.


## Layout

- Use logical CSS properties (`margin-inline-start`) so RTL works.
- Set `lang` and `dir` on the root element.


## Testing

- `@i18n` scenarios use `Scenario Outline` across supported locales.
- Pseudo-locale in development to catch hardcoded strings (if the
  library supports it).
